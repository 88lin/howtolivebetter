# 中文原书自动同步

数据源：[eternity4719/HowToLiveBetter](https://github.com/eternity4719/HowToLiveBetter) 的 `main` 分支，授权为 CC BY 4.0。每条建议保留原作者仓库和精确提交版本的出处链接。站点视觉、导航和服务实现仍由本项目维护。

## 自动执行

工作流：`.github/workflows/sync-book.yml`，名称 **Sync Chinese book**。每日北京时间 08:23（UTC 00:23）运行；GitHub 可能延迟定时任务。也可在仓库 Actions 中选择该工作流，点击 **Run workflow**。

每次执行：

1. 检出本站 `master` 和原书 `main`，原书只作为数据读取，不执行其脚本或安装其依赖。
2. 测试解析器和编号保护，完整解析 Markdown 字段后在内存中生成全部变更。
3. 更新中文数据与页面。原书正文未变时，忽略与书籍无关的上游提交，不制造空提交。
4. 有变化时检查内容、语言数据和站内资源／路由，再运行 ESLint、TypeScript 和生产构建。
5. 全部通过后，用仓库内置 `GITHUB_TOKEN` 提交并推送 `master`。不需要额外的个人令牌。不强制推送；如果有人同时更新主分支，当前推送会安全失败，下一次从最新主分支重新生成。

通过 `GITHUB_TOKEN` 推送通常不会再触发其他 push 工作流，因此同步工作流自身包含完整构建验证。`Deploy frontend preview` 通过 `workflow_run` 监听本同步任务成功结束，随后从最新 `master` 构建并发布 [GitHub Pages 预览](https://88lin.github.io/howtolivebetter/)，无内容变化的成功运行也会触发预览部署。完整 Node 服务器的部署与本地 checkout 不由该任务更新；本地需要 `git pull --ff-only`，运行中的生产服务需重新构建并启动。

## 同步范围

- `book/*.md` 中带编号的章节、章节首段介绍，以及每条建议的标题、成本、说人话、收益、证据等级、来源、备注和成本标签。
- 中文 `tips-zh.json`，合并数据 `tips.json` 中的中文部分。
- 中文书籍目录、章节正文、建议详情、上下条与相关条目链接、现有精选清单中的原文、首页建议数量和中文更新时间。
- 新条目的本地路径、路由索引，以及 `src/content/howtolivebetter/book-sync.json` 中的来源提交、内容摘要和数量。

原书只提供中文。五种翻译、专题、工具题库、图片、广告和原站授权下载不在同步范围。新增中文建议没有对应译文时，语言菜单落到已有翻译章节。首页离线下载说明不推断远端 PDF 的页数或发布版本。

## 编号与失败保护

清单标记以 `章节号-条目号` 保存。允许追加条目和修订原文；要求原有 ID 继续存在，且未被重排到其他主题。删除旧编号、重复编号、编号空洞、同章超过 99 条、章节集合变化、字段缺失、未知标签或疑似主题替换都会停止同步。此时需要审阅上游变更并明确迁移 ID，不能跳过检查强行覆盖。

身份检查比较原有标题与摘要，是防止常见编号错配的保守检查，不是对语义完全相同的数学保证。大幅重写但主题未变的条目也可能被拦下，应先人工核对。

所有解析和页面生成完成后才开始落盘；每个文件通过临时文件替换，来源记录最后写入。远端只有在全部检查完成后才接收一个完整 Git 提交。`.data/`、用户登录、清单、论坛和双人问答数据库均不参与同步。

## 本地使用

```powershell
# 获取最新版，只展示预计变更
npm run sync:book:preview

# 获取最新版并写入本地工作区
npm run sync:book

# 使用已经检出的干净、固定版本（便于复现）
python scripts/sync-book.py --source-dir temp/book-upstream --write

# 验证
npm run test:book-sync
python scripts/verify-book-sync.py
python scripts/audit-import.py
npm run check
```

本地运行不会自动提交或推送。再次运行同一版本应返回 `changedFiles: 0`。上游副本如果有未提交的书籍变更，脚本会拒绝使用，以确保来源链接准确。内容的提交版本和哈希记录于 `book-sync.json`，日期按北京时间显示。
